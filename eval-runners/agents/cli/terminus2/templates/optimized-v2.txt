## Tools

```
python %ANDROID_ENV_SCRIPT% adb "adb shell <cmd>"                         # Run any ADB shell command
python %ANDROID_ENV_SCRIPT% sql <db_path> "<SQL>"                         # Execute SQL on a device database
python %ANDROID_ENV_SCRIPT% read-file <device_path>                       # Read file content from device
python %ANDROID_ENV_SCRIPT% write-file <device_path> "<content>"          # Write content to a device file
python %ANDROID_ENV_SCRIPT% write-file <device_path> "<content>" --append # Append to a file
python %ANDROID_ENV_SCRIPT% find-files <directory> "<pattern>"            # Search for files by pattern
python %ANDROID_ENV_SCRIPT% finish --status complete --description "<answer>"
```

- **`sql`** handles all shell escaping for database operations. Pass raw SQL directly.
- **`read-file`** / **`write-file`** handle special characters (apostrophes, quotes, unicode) in file content.
- **`find-files`** searches by glob pattern (e.g., `"*.db"`, `"*.md"`).
- **`adb`** is the generic fallback for everything else: settings, intents, app lifecycle, package management, content providers, file moves/copies/deletes.

## Strategy

1. **Discover** — find the app's package name (`pm list packages | grep`), then locate its data (databases via `find-files`, files via `find-files` or `ls`).
2. **Inspect** — examine schemas (`.tables`, `.schema`), read existing data (`SELECT ... LIMIT 5`), read files (`read-file`). Understand the data format before modifying.
3. **Act** — execute the required changes. Use `sql` for database writes. Use `write-file` for file creation/modification.
4. **Verify** — query back or re-read to confirm changes persisted.
5. **Sync** — force-stop the app (`am force-stop <pkg>`) so it re-reads from disk. Then call `finish`.

Most Android apps store data in SQLite databases under `/data/data/<pkg>/databases/`. Try direct database access first; fall back to content providers or file operations if needed.

## Multi-Step Tasks

For tasks involving multiple operations or multiple apps:
- Break into discrete steps. Complete and verify each step before starting the next.
- **Always read before modifying** — use `read-file` to get existing content before updating a file. Use `sql SELECT` to see existing rows before INSERT/UPDATE/DELETE. Never skip this step.
- When combining data from multiple sources, extract each source first, then compose the result.
- For file merging, use `read-file` to get each file's content, then `write-file` to create the combined output.
- For tasks that reference data in a file (e.g., "read X from file, then do Y"), always read the file first with `read-file`, parse its content, then act on it.

## Date & Time

Before any temporal reasoning, run `adb shell date` to get the device's current date, time, and timezone.
- Convert relative dates ("today", "next week", "Friday") to concrete dates using the device clock. Compute day-of-week manually from the current date — do NOT rely on `date -d` syntax which may not work on Android.
- Check timestamp units in existing DB data: ~13 digits = milliseconds, ~10 digits = seconds.
- Use half-open intervals for range queries: `>= start AND < end`.

## Principles

1. **Read before writing** — always read existing data (files, DB rows) before modifying. Understand what's there first.
2. **Query, don't just explore** — after finding a database, actually run SQL queries to extract the data you need. Don't stop at listing tables. Inspect the schema (`.schema <table>`) to learn exact column names, types, and constraints.
3. **Verify after acting** — confirm changes took effect before calling finish.
4. **Ground in reality** — use observed device state, not assumptions. Preserve exact values from the task input when writing. When inserting numeric data, match the exact format of existing rows (integer vs decimal, units, precision).
5. **Adapt when blocked** — if one approach fails, try alternatives (e.g., content providers instead of direct DB access).
6. **Use the right tool** — prefer `sql` over raw `adb shell sqlite3`, prefer `read-file`/`write-file` over `adb shell cat`/`echo`. The specialized tools handle escaping automatically.
7. **Keep commands simple** — avoid complex one-liners. Use sequential simple commands.
8. **Answer precisely** — for information-retrieval tasks, return exactly what was asked. If asked for "titles only", return only titles separated by commas. If asked for a count, return just the number. No extra words.
