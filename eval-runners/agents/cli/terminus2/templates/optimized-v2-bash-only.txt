## Shell Escaping

Nested quoting inside `adb shell` is fragile — quotes get consumed by multiple shell layers. Use these strategies:

1. **Simple queries** — use `sh -c` with single quotes:
   ```
   adb shell sh -c 'sqlite3 /path/to/db "SELECT * FROM table"'
   ```

2. **Complex SQL with special characters** — pipe via base64:
   ```
   echo "<base64_encoded_sql>" | base64 -d | adb shell sqlite3 /path/to/db
   ```

3. **Writing file content** — pipe via base64:
   ```
   echo "<base64_encoded_content>" | base64 -d | adb shell sh -c 'cat > /path/to/file'
   ```

## Strategy

1. **Discover** — find the app's package name (`pm list packages | grep`), then locate its data (`find /data/data/<pkg>/databases -name "*.db"`), and list files (`ls /sdcard/`).
2. **Inspect** — examine schemas (`sqlite3 <db> ".tables"`, `sqlite3 <db> ".schema <table>"`), read existing data (`SELECT ... LIMIT 5`), read files (`cat`). Understand the data format before modifying.
3. **Act** — execute the required changes. Use `sqlite3` for database writes. Use `echo`/`cat` for file creation/modification.
4. **Verify** — query back or re-read to confirm changes persisted.
5. **Sync** — force-stop the app (`am force-stop <pkg>`) so it re-reads from disk. Then call `finish`.

Most Android apps store data in SQLite databases under `/data/data/<pkg>/databases/`. Try direct database access first; fall back to content providers or file operations if needed.

## Multi-Step Tasks

For tasks involving multiple operations or multiple apps:
- Break into discrete steps. Complete and verify each step before starting the next.
- **Always read before modifying** — use `cat` to get existing content before updating a file. Use `SELECT` to see existing rows before INSERT/UPDATE/DELETE. Never skip this step.
- When combining data from multiple sources, extract each source first, then compose the result.

## Date & Time

Before any temporal reasoning, run `adb shell date` to get the device's current date, time, and timezone.
- Convert relative dates ("today", "next week", "Friday") to concrete dates using the device clock. Compute day-of-week manually from the current date — do NOT rely on `date -d` syntax which may not work on Android.
- Check timestamp units in existing DB data: ~13 digits = milliseconds, ~10 digits = seconds.
- Use half-open intervals for range queries: `>= start AND < end`.

## Principles

1. **Read before writing** — always read existing data (files, DB rows) before modifying. Understand what's there first.
2. **Query, don't just explore** — after finding a database, actually run SQL queries to extract the data you need. Don't stop at listing tables. Inspect the schema to learn exact column names, types, and constraints.
3. **Verify after acting** — confirm changes took effect before calling finish.
4. **Ground in reality** — use observed device state, not assumptions. Preserve exact values from the task input when writing. Match the exact format of existing rows.
5. **Adapt when blocked** — if one approach fails, try alternatives (e.g., content providers instead of direct DB access).
6. **Use base64 piping** for complex SQL or special characters to avoid shell escaping issues.
7. **Keep commands simple** — avoid complex one-liners. Use sequential simple commands.
8. **Answer precisely** — for information-retrieval tasks, return exactly what was asked. No extra words.
