# Tier4 Paper Paragraphs

## Introduction Paragraph

Existing mobile agent benchmarks such as AndroidWorld [1] and MobileWorld [2] evaluate agents primarily on GUI interaction — tapping, swiping, typing, and navigating app interfaces. While these benchmarks have driven progress in vision-language agents that operate touchscreens, they overlook a class of practical mobile tasks that users routinely encounter but struggle to accomplish through GUI alone: bulk file management ("organize my screenshots by date"), data aggregation ("how many hours of meetings do I have this month?"), cross-app queries ("which numbers texted me that aren't in my contacts?"), and system introspection ("which apps have location access?"). These tasks are not obscure — they represent latent user needs that go unmet because mobile GUIs were not designed for batch operations, multi-app data correlation, or aggregate computation. A systematic review of all 116 AndroidWorld and 117 MobileWorld tasks confirms that neither benchmark tests content provider queries, SQL database operations, file metadata access, system introspection via `dumpsys`, or cross-app data joins — capabilities that are standard in programmatic device access but inaccessible through screen interaction. AndroidWorld's closest analogues are 5 information-retrieval tasks (e.g., "how many climbing activities this week?"), but these are answerable by reading the app UI without any aggregation query. To address this gap, we introduce a 25-task CLI-advantage benchmark subset within AndroidWorld that tests an agent's ability to leverage programmatic device access — ADB shell commands, Android content providers, SQLite queries, and file system operations. Unlike GUI-only evaluation, this subset reveals a distinct capability axis: CLI agents (Opus 4.6, Sonnet 4) achieve 72–84% success rate, while three state-of-the-art GUI agents (Qwen3-VL-32B, MAI-UI-8B, UI-Venus-1.5-8B) achieve only 0–24%. The benchmark decomposes into 15 tasks that no GUI agent can solve regardless of model capability, 6 tasks where both modalities succeed but CLI requires 1.3–3.7× fewer interaction steps, and 4 genuinely hard tasks where both modalities fail — ensuring the evaluation is neither trivially easy for CLI nor artificially impossible for GUI.

## Experiment Results and Analysis Paragraph

Table X presents results on the 25-task CLI-advantage subset. CLI agents substantially outperform GUI agents: Opus 4.6 with tool-augmented prompts solves 21/25 tasks (84%), while the best GUI agent (MAI-UI-8B) solves only 6/25 (24%). This gap is structural rather than model-dependent — three GUI agents built on different architectures (Qwen3-VL-32B at 8%, MAI-UI-8B at 24%, Venus-1.5-8B at 0%) all fail on the same 15 CLI-exclusive tasks, indicating that the limitation lies in the interaction modality, not the underlying model. On the 6 tasks where both CLI and GUI agents succeed, CLI completes them in 1.3–3.7× fewer steps (e.g., checking 3 app versions takes 6 CLI steps via `dumpsys` versus 22 GUI steps navigating Settings menus). Moreover, the GUI step cost scales linearly with task size — appending a footer to N markdown files requires 6N GUI steps (open, edit, type, save per file) versus approximately 3N CLI steps, making GUI infeasible beyond ~8 items within a 50-step budget while CLI handles 20+ items comfortably. Analysis of GUI failure trajectories across the 15 CLI-exclusive tasks reveals five recurring structural patterns: (1) invisible data — file sizes, audio routing, and app metadata that exist on the device but are not rendered in any app UI; (2) no aggregate views — apps show individual items but provide no totals, counts, or rankings; (3) no cross-app memory — GUI agents lose context when switching between apps, making data correlation impossible; (4) O(N) interaction cost — bulk operations require per-item tap sequences that exhaust step budgets; and (5) no multi-condition filters — apps support single-dimension filtering but not compound queries like "songs by artist X longer than 4 minutes." These patterns describe not agent failures but fundamental limitations of screen-based interaction that CLI access bypasses through direct data queries, shell scripting, and content provider APIs.
