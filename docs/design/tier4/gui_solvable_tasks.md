# Tier4 Tasks Solvable by GUI Agent (Qwen3-VL-32B)

16/50 tier4 tasks were solved by Qwen3-VL-32B (GUI agent, 50 steps, real goals).
These tasks can be completed through visual UI interaction despite being designed
as ADB-exclusive.

## Summary

| Category | Tasks Solved | Pattern |
|----------|-------------|---------|
| Files (browse + delete/edit) | 3 | Open Files/Markor app, visually select and act |
| SMS (read counts/threads) | 2 | Open SMS app, count or read visible messages |
| Contacts (read info) | 1 | Open Contacts, read name from list |
| Expense (browse + read) | 4 | Open Pro Expense, navigate to logs/stats |
| Tasks.org (read status) | 1 | Open Tasks app, read overdue status |
| Joplin (search + read) | 2 | Open Joplin, use search, read results |
| OpenTracks (read + cross-app) | 2 | Open OpenTracks, read stats, create task |
| Markor (edit files) | 1 | Open Markor, edit each file one by one |

## Task 0: Tier4BulkDeleteTmpInDownloads

**Goal**: Delete all .tmp files in the Downloads folder.

**Agent Strategy** (9 steps):
1. Swipe up to open app drawer
2. Open Files app
3. Long-press first .tmp file to enter selection mode
4. Long-press remaining .tmp files (3 more) to multi-select
5. Tap delete icon (trash)
6. Confirm deletion
7. Verify Downloads folder is empty
8. Call terminate(success)

**Why GUI works**: Files app shows .tmp files visually; multi-select + delete is a standard UI operation.

**Verifier**: Device-state — runs `find /sdcard/Download -name *.tmp` and checks output is empty.

## Task 8: Tier4BulkAppendFooterToMarkdown

**Goal**: Append `---\nGenerated by AutoBot` to every .md file in Markor's Notes folder.

**Agent Strategy** (24 steps):
1. Open Markor app
2. For each of 4 .md files:
   - Tap file to open → tap edit mode
   - Type `---\nGenerated by AutoBot`
   - Navigate back (×2) to return to file list

**Why GUI works**: Markor provides a text editor. The agent opens each file, scrolls to bottom, types the footer. Tedious (24 steps for 4 files) but achievable.

**Verifier**: Device-state — runs `tail -2` on each .md file and checks for footer text via `grep`.

## Pattern Analysis

The 16 GUI-solvable tasks share these characteristics:

1. **Information is visually accessible** — counts, names, amounts, file lists are displayed in app UIs
2. **Standard UI operations suffice** — open app, browse, read, select, delete, type
3. **No bulk/batch operations** — tasks that require processing many items (rename 10 files, query 100 SMS) fail via GUI
4. **No hidden state** — tasks querying system permissions, audio routing, WiFi state are not in any app UI
5. **No complex data joins** — cross-app tasks requiring matching data between databases fail via GUI
6. **No precise temporal queries** — tasks requiring date-range filtering of database records fail via GUI

The 34 GUI-failed tasks require: bulk file operations (rename, move), database queries (SQL on content providers), system state inspection (dumpsys, getprop), or multi-app data correlation — operations only available via ADB shell.
