## Allowed ADB commands

Commands run through a security whitelist. ONLY these prefixes are accepted:

**App management**: `am start`, `am force-stop`, `am broadcast`, `pm list packages`, `pm list features`, `pm grant`, `pm clear`
**Content providers**: `content query`, `content insert`, `content delete`, `content update`
**System info**: `dumpsys`, `settings get`, `settings put`, `getprop`, `date`, `whoami`, `wm size`, `wm density`
**Connectivity**: `svc wifi enable/disable`, `svc bluetooth enable/disable`
**File operations**: `ls`, `cat`, `find`, `mkdir`, `rm`, `mv`, `cp`, `touch`, `echo`, `printf`, `sed`
**Shell**: `sh -c '<command>'` (use this for pipes and complex commands)
**Other**: `input tap/swipe/text/keyevent`, `cmd`, `sleep`, `monkey`

**NOT allowed** (will return HTTP 400):
- `run-as` — no access to private app data directories
- `su` — device is not rooted
- `sqlite3` directly — not on the PATH; use `sh -c` to pipe SQL (see below)
- `pm path`, `pm dump` — not whitelisted
- `adb pull/push` — not supported

## Exploration strategy

ALWAYS explore before acting. The key to solving app tasks is discovering how to access app data through **allowed** commands.

### Step 1: Discover the app
```
adb shell pm list packages | grep -i <keyword>
adb shell dumpsys package <package> | grep -i provider     # Find content providers
adb shell dumpsys package <package> | grep -i database      # Find database references
```

### Step 2: Discover content providers
Content providers are the primary way to read/write app data. Discover them:
```
adb shell dumpsys package <package> | grep -A5 "ContentProvider"
adb shell dumpsys package <package> | grep -i authority
```
Then query, insert, delete, or update using the discovered URIs:
```
adb shell content query --uri content://<authority>/<table>
adb shell content query --uri content://<authority>/<table> --where "<column>='<value>'"
adb shell content delete --uri content://<authority>/<table> --where "<column>='<value>'"
adb shell content insert --uri content://<authority>/<table> --bind <column>:s:<value>
```

### Step 3: Explore file system
Apps may store data on shared storage. Discover paths by exploring:
```
adb shell ls /sdcard/
adb shell find /sdcard/ -type f -name "*.txt" -o -name "*.md" -o -name "*.db"
```

### Step 4: Use shell pipes for complex operations
Wrap pipes and complex commands in `sh -c`:
```
adb shell sh -c 'cat /path/to/file | grep pattern'
adb shell sh -c 'echo "SELECT * FROM table;" | sqlite3 /path/to/database.db'
adb shell sh -c 'ls /some/dir/*.txt | wc -l'
```

## Principles

1. **Explore extensively first** — spend your first 2-3 turns discovering app structure, content providers, and file locations before making any changes.
2. **Verify after acting** — confirm your changes took effect before calling finish.
3. **Ground in reality** — use observed device state for dates, times, and values. Do not guess.
4. **Pipe via sh -c** — for pipes and complex commands:
   `adb shell sh -c '<command1> | <command2>'`
5. **Use programmatic APIs** — prefer content providers, file operations, and am/pm commands.
6. **Adapt when blocked** — if a command returns HTTP 400, it's not whitelisted. Try an alternative approach using allowed commands.
